# Контракты документов

Модели находятся в `src/tz_auditor/domain/documents.py`, используют Pydantic v2.
Новые обязательные поля и изменения значений согласовываются до реализации.

## SourceLocator

| Поле | Тип | Значение |
| --- | --- | --- |
| paragraph_index | int или null | Индекс абзаца среди абзацев верхнего уровня |
| table_index | int или null | Индекс таблицы среди таблиц верхнего уровня |
| row_index | int или null | Индекс строки таблицы |
| column_index | int или null | Индекс физической XML-ячейки w:tc среди ячеек строки |

Все индексы начинаются с нуля. Отрицательные числа, bool, строки и дробные
числа отклоняются. Незаданные поля по умолчанию равны null.
Допустимы ровно две формы:

```json
{"paragraph_index": 0, "table_index": null, "row_index": null, "column_index": null}
```

```json
{"paragraph_index": null, "table_index": 0, "row_index": 1, "column_index": 2}
```

Пустой адрес, неполные координаты ячейки и смешение двух форм отклоняются.
Абзацы внутри ячеек не участвуют в paragraph_index. Вложенные таблицы не
участвуют в table_index. Пустые абзацы и обычные пустые ячейки сохраняются.

Для сложных таблиц column_index указывает физическую ячейку, а не столбец сетки
Word: горизонтальное объединение gridSpan занимает один физический адрес.
Например, строка из ячейки с gridSpan=2 и следующей ячейки имеет column_index 0 и 1,
хотя в визуальной сетке следующая ячейка начинается в столбце 2. Пропуски сетки
gridBefore/gridAfter не создают фиктивных ячеек и не сдвигают физические индексы.
Чтобы найти оригинал, следует взять `table._tbl.tr_lst[row_index].tc_lst[column_index]`;
`table.cell()` и `row.cells` могут возвращать повторные ссылки для объединений.
Для обычных прямоугольных таблиц значения координат остались прежними.

Пустые продолжения однозначно распознанных vMerge/hMerge не создают блоков:
текст начала объединения не копируется. Если в продолжении есть собственный
непробельный текст, он сохраняется отдельным блоком по физическому адресу
продолжения. Источник связи и аномальное содержимое обозначаются в warnings.
При потере или неоднозначности начала продолжение сохраняется, даже если пустое.
Устаревшие hMerge не склеивают тексты разных физических ячеек: каждый фрагмент
имеет свой исходный адрес. Строки обрабатываются независимо от полноты соседних строк.
Ошибки геометрии не меняют физические адреса и не приводят к пропуску всего текста.
Это расширяет поведение на ранее пропускавшиеся таблицы; поля моделей не изменены.

## DocumentBlock

| Поле | Тип | Правило |
| --- | --- | --- |
| block_id | str | Парсер выдаёт b000001, b000002 и далее |
| order | int | Последовательность извлечённых блоков с нуля |
| kind | paragraph или table_cell | Должно соответствовать форме locator |
| text | str | Текст, включая пустую строку; абзацы ячейки разделены `\n` |
| section_path | list[str] | Заголовки действующих разделов от старшего к младшему |
| heading_level | int или null | 1–9 для стандартного Heading, иначе null |
| locator | SourceLocator | Адрес в исходном документе |

`heading_level` по умолчанию null; ячейка не может определять заголовок раздела.
Сначала идёт абзац или заголовок, затем все ячейки встретившейся таблицы по строкам,
затем следующие элементы основного тела. Повторные позиции объединённых ячеек
не заполняются копиями текста. Уникальность block_id и непрерывность order
обеспечиваются парсером. ID блоков локальны для документа, не являются глобальными.

Заголовок входит в собственный section_path. Новый Heading N удаляет из текущего
пути все прежние заголовки уровня N и глубже, затем добавляется сам.
Например, Heading 1 «А», Heading 2 «Б», Heading 3 «В», Heading 2 «Г» дают пути
`["А"]`, `["А", "Б"]`, `["А", "Б", "В"]`, `["А", "Г"]`.
Пропущенные уровни не заполняются выдуманными названиями: Heading 1 «А»,
Heading 3 «В» дают `["А", "В"]`. До первого заголовка путь пустой.
Таблица наследует путь раздела в месте её появления. Стиль Heading внутри
ячейки не меняет путь. Каждый блок содержит независимый снимок пути.

## ParsedDocument

| Поле | Тип | Правило |
| --- | --- | --- |
| document_id | str | SHA-256 исходных байтов DOCX: 64 шестнадцатеричных символа |
| filename | str | Имя файла без каталогов |
| blocks | list[DocumentBlock] | Все извлечённые блоки в исходном порядке |
| warnings | list[str] | Предупреждения о пропусках и ограничениях |

Для пустого документа blocks и warnings пусты. На неизменном файле весь результат
детерминирован. Переименование меняет filename, но не хэш. Изменение байтов
файла меняет хэш, даже если видимый текст тот же. Идентификаторы и SHA-256
формирует парсер; сами модели не требуют предоставлять реальные файлы.

Сериализация: `model_dump_json(indent=2)`; обратная проверка:
`ParsedDocument.model_validate_json(json_text)`. JSON записывается CLI в UTF-8
без экранирования русских символов. Ошибки чтения, неподдерживаемые расширения
и повреждённые DOCX приводят к `DocxParseError`, а не к фиктивному пустому документу.
