# TZ-Auditor

Интеллектуальная система проверки технических заданий на закупку товаров, работ
и услуг в рамках 223-ФЗ. Первый этап реализует только локальное извлечение
структуры DOCX: абзацы, ячейки таблиц, заголовки и точные адреса источников.
Смысловой анализ, проверка законодательства и выявление противоречий пока отсутствуют.

## Установка

Нужны Python 3.11+ с модулем venv и pip. В WSL выполняйте команды в `/root/tz-auditor`
или в своей локальной копии репозитория. Python 3.10 не поддерживается.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
```

Загрузка зависимостей требует сети только во время установки. Обработка документов,
генератор и тесты выполняются локально, без интернета, GPU и внешних сервисов.

## Синтетические примеры и CLI

```bash
python scripts/generate_synthetic.py
mkdir -p outputs
python -m tz_auditor parse tests/fixtures/synthetic/shelves.docx --output outputs/shelves.json
python -m tz_auditor parse tests/fixtures/synthetic/shelves_conflict.docx --output outputs/conflict.json
```

Генератор создаёт два документа для вымышленной организации «Пример-Склад»
в `tests/fixtures/synthetic/`. В `shelves.docx` высота стеллажа в описании и таблице
равна 2000 мм. В `shelves_conflict.docx` описание содержит 2000 мм, а таблица —
2200 мм. Парсер извлекает оба значения, но не классифицирует их как противоречие.
Можно указать другую папку: `python scripts/generate_synthetic.py --output-dir /tmp/synthetic`.

JSON сохраняется в UTF-8 с читаемым русским текстом. Родительская папка результата
должна существовать; существующий JSON перезаписывается. Перезапись входного файла
запрещена. Ошибки выводятся в stderr и возвращают ненулевой код завершения.
Предупреждения об ограничениях также выводятся в stderr и включаются в JSON.

Пример первого блока (сокращённое представление документа):

```json
{
  "block_id": "b000001",
  "order": 0,
  "kind": "paragraph",
  "text": "Закупка металлических стеллажей",
  "section_path": ["Закупка металлических стеллажей"],
  "heading_level": 1,
  "locator": {
    "paragraph_index": 0,
    "table_index": null,
    "row_index": null,
    "column_index": null
  }
}
```

## Проверки

```bash
pytest -q
ruff check .
```

Тесты сами генерируют синтетические документы во временной папке. Проверяются
координаты, порядок, пустые элементы, section_path, идентификаторы, ошибки,
сериализация и CLI. Ни реальные ТЗ, ни внешние сервисы для тестов не нужны.

## Ограничения первого этапа

- Поддерживаются только DOCX и основное тело документа. PDF, DOC и DOCM не поддерживаются.
- Заголовки распознаются по стандартным стилям Heading 1–9; визуальное форматирование,
  пользовательские стили и текстовая нумерация сами по себе не определяют раздел.
- Текст абзацев ячейки объединяется через `\n`. Заголовки внутри ячеек не меняют
  иерархию разделов основного документа.
- Поддерживаются горизонтальные `gridSpan`, вертикальные `vMerge` и прямоугольные
  объединения. Текст исходной ячейки извлекается один раз. Пустые продолжения
  распознанных объединений не создают блоков; обычные пустые ячейки сохраняются.
- `column_index` — индекс физической XML-ячейки `w:tc` внутри строки, а не визуальный
  столбец сетки Word. После горизонтального объединения или пропуска слева эти
  числа могут различаться. В обычных таблицах поведение не изменилось.
- Неполные строки, `gridBefore`/`gridAfter`, отсутствующая сетка и некорректные
  размеры не приводят к пропуску таблицы: доступный текст сохраняется с исходными
  физическими координатами и диагностикой. Геометрия повреждённых таблиц может
  оставаться неопределённой. При неоднозначном продолжении его текст сохраняется
  отдельно; текст якоря не копируется.
- Устаревшие горизонтальные `hMerge` поддерживаются частично: доступны исходные
  тексты и диагностика связей, но содержимое разных физических ячеек не склеивается.
  Собственный текст продолжения `vMerge` также сохраняется отдельным блоком.
- Модели не содержат размеров объединений. Диапазоны и связи объединений отражаются
  диагностикой в `warnings`; JSON не предназначен для точного восстановления макета.
- Вложенные таблицы пропускаются с предупреждением; обычные абзацы внешней ячейки
  сохраняются. Количество пропущенных элементов не меняет индексы следующих таблиц.
- Колонтитулы, изображения, графические объекты и текстовые поля не извлекаются.
  При их обнаружении выдаются предупреждения. Неподдерживаемые контейнеры основного
  тела, например элементы управления содержимым, пропускаются с предупреждением.
- Не восстанавливаются отображаемые номера автоматических списков, поля Word,
  сноски, комментарии, история исправлений, форматирование и номера страниц.
  Текст таких конструкций может отсутствовать в результате. Это не полный экспорт Word.
- Хэш стабилен для одинаковых байтов DOCX. Повторное сохранение в Word или
  повторная генерация ZIP может изменить хэш даже при одинаковом видимом тексте.

Данные обрабатываются только локально. Для разработки использовать исключительно
синтетические документы. Реальные и конфиденциальные ТЗ в репозиторий не добавлять.
