# Правила разработки TZ-Auditor

- Реализовывать только согласованное ТЗ; архитектурные решения обсуждаются отдельно.
  Об архитектурной проблеме сообщить до изменения реализации или контрактов.
- Сохранять модульность и типизацию Python 3.11+. Не менять согласованные модели
  SourceLocator, DocumentBlock, ParsedDocument без обсуждения.
- Обрабатывать документы локально. Не передавать их текст, таблицы или фрагменты
  внешним API; не подключать облачные LLM или сервисы обработки документов.
- Использовать только синтетические документы и тесты. Не читать и не копировать
  реальные ТЗ МФТИ и другие конфиденциальные документы.
- Не включать секреты, .env, реальные документы, окружения и результаты обработки в Git.
- Для изменений парсера и контрактов обязательны тесты на корректность координат,
  порядка, section_path и сериализации. Перед сдачей запускать pytest -q и ruff check .
- Тесты должны выполняться без сети, GPU, Ollama и внешних сервисов.
- Работать в feat/docx-parser для первого этапа. Не сливать в main и не отправлять
  изменения на GitHub без отдельного разрешения пользователя.
- Не создавать преждевременно модули LLM, RAG, API или следующие этапы проекта.
